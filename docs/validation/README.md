# 验证记录

## 2026-10-04 连续分拣与自动回位

一次 `/pick/start` 自动完成红、绿、蓝三个色块的分拣。每个色块放置后通过 MoveIt 回到仿真启动时的关节姿态，再使用新的 RGB-D 图像判断是否还有色块。连续确认桌面为空后结束，机械臂保持初始姿态。

在本工作区实际执行两轮完整无窗口仿真（两轮之间调用复位），结果：

- 2/2 轮通过，共 6 次放置；每轮只调用一次启动服务。
- 每轮的初始扫描和三次放置后扫描，都检查了回位；实测最大关节偏差小于 0.003 rad。
- 每轮结束时三个物体都留在对应容器底部，未因机械臂回位而重置。
- `SUCCEEDED` 后继续观察 2 秒仿真时间，机械臂保持初始姿态，关节变化小于 0.001 rad，没有再次启动动作。
- 6 个回归测试通过，包括空桌面确认的去重、时长、数据过期和断流检查，以及原有 30 秒夹持测试。

详细结果见 [auto_sort.json](auto_sort.json)。运行 `scripts/validate_demo.py --launch --trials 2` 可复现两轮完整分拣。

## 2026-10-04 抓取放置修复

本工作区在 Ubuntu 22.04 虚拟机、ROS 2 Humble、MuJoCo 3.13.0 上实际验证：

| 项目 | 结果 |
|---|---|
| 红色抓取放置，包含复位重试 | 2/2 成功 |
| 绿色抓取放置，MuJoCo / RViz / 相机窗口开启 | 1/1 成功 |
| 蓝色抓取放置 | 1/1 成功 |
| 搬运时双指接触、放下后在同色容器底部静止 | 全部通过 |
| 30 秒物理夹持，随后开爪自由释放 | 通过；关闭修正参数后新回归测试失败，提示 `Grasp is creeping` |
| 几何、轨迹和物理回归测试 | 4 passed |
| 非法指令、并发指令、取消、夹爪开合、复位检查 | 通过 |

原实现存在两个主要问题：默认软接触求解使色块在静止夹持时仍持续下滑；任务在抬升后直接报告成功，没有放置阶段。修复开启接触求解的 no-slip 迭代，并补齐搬运、释放、退回和放置验证。接近姿态使用当前关节状态作为 IK 种子。放置时掌部保持在箱沿上方，避免与窄容器开口碰撞。

详细落点、状态序列和测试条件见 [pick_place_fix.json](pick_place_fix.json)。这些结果针对仓库自带的固定场景。

## 历史抬升验证

以下为清理前项目文档中记录的结果，原始报告未包含在本仓库中，不代表每次环境安装后的实测结果；请按使用说明重新运行验收脚本。

验证环境：Ubuntu 22.04 容器、ROS2 Humble、MoveIt2、MuJoCo 3.13.0、Python 3.10。验证脚本为 `scripts/validate_demo.py`，它只把 `/simulation/grasp_metrics` 作为验收真值，不提供检测目标。

| 项目 | 结果 |
|---|---|
| 红色目标，两次连续抓取 | 2/2 成功 |
| 蓝色目标，一次抓取 | 1/1 成功 |
| RGB-D 与识别图 | 运行中持续发布 |
| 视觉到 MuJoCo 真值误差 | 红 0.02–1.12 mm，绿 2.08 mm，蓝 1.57 mm |
| 物体实际抬升 | 约 86.8–90.9 mm |
| 抬升后双指接触保持 | 通过，连续检查 2 秒仿真时间 |
| MuJoCo / ROS 时间推进 | 通过 |
| malformed trajectory / 并发 action / 忙时 reset | 均按预期拒绝 |
| 取消轨迹 | 通过，保持实际关节位置 |
| 夹爪 0 / 0.04 m 单指行程 | 开合与到位反馈通过 |
| 内参、反投影、轨迹、URDF/MJCF TCP 回归测试 | 3 passed |

测试脚本会生成 `report.json`、`launch.log` 和抓取前后的图像。软件渲染时实际相机频率取决于机器；本次 3.13.0 EGL 验证约 5.7 Hz，配置仍为 15 Hz。机器人关节状态约 68–88 Hz，仿真速度约 0.68–0.88 倍实时。独立 Ubuntu 电脑若有 GPU，通常会更快。

示例识别画面：[camera_detection.png](../camera_detection.png)。图中标签是 TF2 转换后的 `fr3_link0` 坐标，不是摄像头坐标。

关闭 launch 时，容器中的 MoveIt Humble 2.5.10 曾在析构阶段打印上游 segmentation fault；它发生在所有任务和报告已完成之后，不能代表执行失败。正常启动、规划、action 和物理抓取均在退出前通过。
